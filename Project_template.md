### Сравнение LLM
| Критерий                     | Локальные модели (Hugging Face)                               | OpenAI (GPT-3.5-turbo / GPT-4)                              | YandexGPT                                                  |
|------------------------------|-------------------------------------------------------------|-----------------------------------------------------------|------------------------------------------------------------|
| **Качество ответов**         | Хорошее для технических доменов при дообучении; требует тонкой настройки | Отличное, особенно в логике, структурировании, объяснении | Хорошее, но хуже, чем GPT-4 на сложных задачах             |
| **Скорость работы**          | Медленнее (особенно без GPU); зависит от железа             | Очень высокая (оптимизированные серверы)                  | Высокая (облачные серверы Яндекса)                         |
| **Стоимость владения**       | Высокая начальная (железо, обучение), но нулевая за инференс после развёртывания | Плата за токены; масштабируется с использованием           | Плата за токены; дешевле OpenAI, но дороже локальных       |
| **Удобство развёртывания**   | Сложное: нужно управлять GPU, кэшированием, API, обновлениями | Простое: REST API, SDK, стабильность                      | Простое: API, но интеграция с AWS/Slack может быть сложнее |
| **Конфиденциальность**       | Полный контроль над данными                                 | Данные уходят в облако OpenAI                             | Данные в Яндексе, возможны ограничения по GDPR             |

### Сравнение моделей эмбедингов
| Критерий                     | Sentence-transformers (локальные)                           | Open embeddings (text-embedding-3-small/large)                            |
|------------------------------|--------------------------------------------------------------|------------------------------------------------------------|

| **Качество поиска**          | Хорошее, особенно при fine-tuning на технических текстах     | Отличное out-of-the-box, особенно на английском            |
| **Стоимость владения**       | Нулевая после развёртывания (разве что электричество)        | $0.0001 / 1k токенов — при 18k Markdown-файлов и 3k Confluence-страниц это может быть тысячи запросов в день → дорого |
| **Конфиденциальность**       | Данные не покидают внутреннюю сеть                           | Все документы уйдут в OpenAI                               |

### Рекомендуемая конфигурация сервера

#### Для размещения RAG-бота с локальной LLM и векторной БД:

**Вариант 1: CPU-only (бюджетный, MVP)**  
CPU: 8 ядер (Intel Xeon или AMD EPYC)  
RAM: 32 ГБ (для загрузки модели + индекса FAISS)  
Диск: 100 ГБ SSD (для индекса, моделей, логов)  
GPU: отсутствует  
Модели:  
LLM: Mistral-7B-GGUF (q4_0) — ~4.5 ГБ RAM  
Embedding: all-MiniLM-L6-v2 (~100 МБ)  
**Плюсы:** дешево, просто, безопасно  
**Минусы:** медленная генерация (~5-10 токенов/сек)  

**Вариант 2: GPU-ускоренный (production-ready)**  
CPU: 8 ядер  
RAM: 64 ГБ  
GPU: NVIDIA T4 (16 ГБ VRAM) или A10G  
Диск: 200 ГБ NVMe  
Модели:  
LLM: Mistral-7B или Llama 3 8B в FP16 (~14 ГБ VRAM)  
Embedding: BAAI/bge-base-en-v1.5 на GPU  
**Плюсы:** высокая скорость (20-30 токенов/сек), хорошее качество  
**Минусы:** дороже, сложнее обслуживать  

**Вариант 3: Облачный LLM (не рекомендуется)**
Использовать OpenAI GPT + OpenAI Embeddings
**Плюсы:** Простота, качество  
**Минусы:** Нарушение политики безопасности, дороговизна при масштабе, не подходит для SOC 2  

**Вариант 4: Гибрид (рекомендуемый компромисс)**  
Embedding: локальный (BAAI/bge-base-en-v1.5)  
Векторная БД: FAISS (на диске)  
LLM: локальный Mistral-7B-GGUF на CPU (с квантованием)   
Инфраструктура: виртуальная машина в AWS (16 vCPU, 32 ГБ RAM) или on-premise 

#### Рекомендуемая конфигурация инфраструктуры

| Компонент           | Выбор                                               | Обоснование                                                                                                   |
|---------------------|-----------------------------------------------------|---------------------------------------------------------------------------------------------------------------|
| **LLM**             | Локальная модель: Mistral-7B (GGUF, q4_0)          | Баланс качества и потребления памяти, работает на CPU, не требует GPU                                        |
| **Embedding модель**| BAAI/bge-base-en-v1.5 (Sentence-Transformers)           | Лёгкая, качественная, open-source, работает на CPU                                                           |

| **Инфраструктура**  | Виртуальный сервер (AWS или on-premise) с 32 ГБ RAM, 16 vCPU | Достаточно для индексации и инференса                                                                         |
| **Развёртывание**   | Docker + Docker Compose                             | Изоляция, переносимость, простота деплоя                                                                      |

### Выбор модели эмбедингов
Название модели: BAAI/bge-base-en-v1.5  
Ссылка: https://huggingface.co/BAAI/bge-base-en-v1.5  
Тип: Локальная, Sentence-Transformers  
Размер эмбеддингов: 768 (768-мерные векторы)  
Размер модели: ~440 МБ  
Преимущества: Высокая точность семантического поиска, особенно на технических и повествовательных текстах; нормализованные эмбеддинги оптимальны для косинусного сходства  
Использование: Работает на CPU и GPU; рекомендуется использовать с GPU при высокой нагрузке, но корректно функционирует и на CPU  

### Подготовка чанков

Размер чанка: 256 токенов (~180–220 слов)  
Overlap: 64 токена (для сохранения контекста между частями)
Разделители: \n\n, \n, . , ! , ? , пробел — настроены в RecursiveCharacterTextSplitter  
Цель: сохранить логическую целостность абзацев (например, не разрывать описание персонажа посередине);  
Обоснование: слишком большие чанки (например, 500+ токенов) снижают точность поиска, слишком мелкие — теряют контекст. 256 токенов — оптимальный баланс для bge-base-en-v1.5
